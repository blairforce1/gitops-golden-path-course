# 0002. Protect `main` from day zero and route every change through a PR

- **Status:** accepted
- **Date:** 2026-08-26
- **Deciders:** blairforce1, with Claude Code
- **Supersedes:** none

## Context

A config repo has one write path that matters: what reaches `main`, because `main` is what the fleet reconciles. A direct push that touches `apps/base/` reaches every cluster at once with no diff read by anyone. Every later control the platform adds hangs off the pull request: commit statuses on the merge commit, CI as a required check, the rendered diff as a comment, code-owner review, the freeze gate, the work-item check. If the PR is adopted late, each of those controls arrives as a workflow change; if it is adopted before the first commit, each arrives as one line added to a thing already done. Teams under four-eyes controls (SOC 2, ISO 27001) cannot follow a workflow that pushes direct at all.

## Decision

A ruleset on `main` exists from the day the repo is created: pull request required, force-push and deletion blocked, linear history off, **no bypass actors** (not the admin, not the robot). Every change reaches `main` as a merged PR, human or robot, config or tooling. The ruleset is amended per act (`scripts/ruleset require-check`, `require-owners`), never replaced. Approvals are 0 where one person operates the repo, because GitHub forbids self-approval; a team sets 1. The trade is stated up front: a little friction while diffs are one line, muscle memory within a few changes, and every later control lands as a payoff.

## Considered options

- **Protect `main` at the first production change.** Five stages of a workflow that is then unlearned; a mistaken push to `base/` is caught late instead of early; four-eyes readers must fork the process. Rejected.
- **A bypass actor for the robot or a deploy key.** The robot would skip the check that was just made required, and a credential would become an identity. Rejected: the robot writes to its own branch, a workflow opens the PR with the repository token and arms auto-merge on the same required checks a human waits for.
- **`flux bootstrap` pushing to `main`.** Incompatible with no-bypass. The bootstrap manifests are generated by the CLI, merged by PR, and `scripts/cluster-sync` does the cluster half; git then holds the components, so no bootstrap flags have to be remembered.

## Consequences

- Easier: every control is attached to an artifact that already exists; the merge is the gate and reading the diff is the habit.
- Harder: a paid GitHub plan is required for rulesets on a private repo. On the free plan the practice survives and the enforcement does not, in seven named places.
- Harder: four-eyes cannot be demonstrated solo; the record honestly shows approvals 0.
- Follow-up: `pr-open` (never merges) and `pr-revert` (`git revert -m 1` by PR) exist so that the seven-line flow is typed a few times, then scripted.
